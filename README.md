# IEJoin-style batch inequality-join backend

Two-table batch join with **exactly two range predicates**
(`L.x <op1> R.x AND L.y <op2> R.y`), implemented in the IEJoin style:
two sorted permutations + position maps, equality-group-aware
monotone gates, and a single candidate bitmap. Built with
**Rust + Axum + arrow2**, using only local synthetic data — no
external accounts or business data.

## What it does

Given two typed columnar batches and two inequality predicates (each
one of `<`, `<=`, `>`, `>=`), it emits the multiset of matching row
pairs, preserving:

- **all four inequality directions**, with strict vs non-strict
  boundaries handled differently on equal values;
- **duplicate rows** — physically identical rows keep distinct caller
  identities and full Cartesian multiplicity;
- **NULL semantics** — a NULL on either key never matches (SQL
  three-valued logic); NULL rows are excluded from the permutations;
- **exact candidate accounting** — counters report right rows scanned,
  gate steps and candidate bitmap accesses;
- **controlled output** — an explicit pair budget either truncates a
  one-shot request (`truncated: true`) or pages deterministically via
  resumable cursors.

## Algorithm and boundary semantics

For `L.x <op1> R.x AND L.y <op2> R.y`:

1. Build **two** ascending/descending permutations of the **left**
   relation, one per predicate key, each with a position map. NULL rows
   map to no position.
2. Scan **right** rows sorted by predicate-1 key, dropping rows NULL on
   either key.
3. A group-aware monotone gate walks left permutation 1. Equal values
   form explicit equality groups: a strict gate stops just below a
   group, a non-strict gate enters it whole. This is the strict/
   non-strict boundary difference and the guarantee that no equal-value
   group is missed or admitted one row early.
4. Activated left rows are translated through permutation 2's position
   map into one candidate bitmap. Monotonicity means bits are only ever
   set, never cleared; bit updates happen per whole group **before** the
   prefix is read.
5. Predicate 2's matches are a permutation-2 prefix `[0, bound2)`;
   output pairs are exactly the set bits in that prefix.

**Reference oracle.** A separate, brute-force nested-loop join in
`src/operator/reference.rs` shares no algorithm code with the core.
Tests compare the IEJoin multiset against (a) hand-computed literal
expectations in `src/fixtures.rs` and (b) this independent reference.
The reference answers are therefore not generated by the code under
test.

### Multiset, identity and ordering

- Output is a **multiset** of `(left_id, right_id)`; identical values
  with different ids are distinct; every qualifying combination appears
  exactly once per page sequence.
- Row order within a one-shot response follows the internal scan, but
  tests compare as multisets, never relying on incidental order.
- Cursors resume exactly — including mid-right-row — so pagination
  neither duplicates nor drops pairs.

### Error categories

Every failure is one of four distinguishable categories:

| category             | code examples                        | HTTP | exit code |
|----------------------|--------------------------------------|------|-----------|
| `input`              | `predicate_count`, `unknown_column`, `unsupported_comparator`, `invalid_json` | 400  | 2 |
| `state_conflict`     | `unknown_cursor`                     | 409  | 3 |
| `resource_exhausted` | `input_too_large`, `output_budget_reached`, `cursor_batch_limit` | 413  | 4 |
| `compute`            | `checkpoint_shape_mismatch`, `trace_parse_failed`, `replay_diverged` | 500  | 5 |

## Layout

```
src/
  error.rs             four-category error contract
  batch.rs             typed nullable columns + arrow2 conversion
  dto.rs               JSON wire contract + request validation
  resource.rs          explicit budgets
  state.rs             checkpoints + cursor sessions
  trace.rs             replayable run records (run id, events, outcome)
  engine.rs            orchestration, fingerprints, paging, arrow render
  fixtures.rs          synthetic scenarios + hand-computed answers
  operator/
    comparator.rs      <, <=, >, >= + NULL-aware eval
    permutation.rs     sort permutations, position maps, group gate
    bitmap.rs          dense bitset + counters
    plan.rs            two-predicate plan + validation
    iejoin.rs          core: prepare / run_all / resumable runner
    reference.rs       independent nested-loop oracle
  api/mod.rs           Axum router (/v1/join, /v1/cursors, ...)
  cli.rs               serve | run | verify | request | replay
  main.rs              binary entry
tests/                 integration tests (see below)
examples/              sample JSON requests
scripts/verify.sh      verification entry point
```

## Build and test

```bash
# isolated CARGO_HOME is optional; avoids lock contention on shared boxes
export CARGO_HOME="$PWD/.cargo-home"
cargo build
cargo test                 # unit + integration suite
./scripts/verify.sh        # fmt + clippy + tests + CLI/HTTP smoke
```

Fixed/pinned dependency versions live in `Cargo.toml` (`=x.y.z`) and
the committed `Cargo.lock`.

### CLI

```bash
./target/debug/iejoin verify                       # all scenarios vs oracle
./target/debug/iejoin run --scenario selective --json
./target/debug/iejoin request --file examples/grid_le.json
./target/debug/iejoin serve --addr 127.0.0.1:8080
```

With `--trace-dir DIR`, every run writes `DIR/<run_id>.json` containing
the run id, plan/input summary, budget, intermediate events (gate
cursor, bitmap popcount, predicate-2 bound, per-step rationale),
counters, outcome and error snapshot. `replay` rebuilds identical local
inputs and asserts the recorded outcome/counters are reproduced.

### HTTP

```
POST /v1/join          one-shot (truncated flag on budget overflow)
POST /v1/cursors       open a paged cursor, returns page 1
POST /v1/cursors/next  next controlled page; cursor closes on last page
GET  /healthz
```

## Test coverage of the required questions

- `tests/iejoin_vs_reference.rs` — all four directions, all-equal
  (strict empty / non-strict full Cartesian), both empty sides, NULLs;
  exact multiset vs hand answers and the nested-loop reference.
- `tests/differential.rs` — exact candidate-access count on the
  high-selectivity fixture (6 probes vs 100 nested-loop evaluations),
  plus 400 seeded random small cases (duplicates, NULLs, empties) across
  all directions and denser cases.
- `tests/error_contract.rs` — concrete category+code assertions for
  malformed plans/inputs and resource exhaustion, not "it can be called".
- `tests/cursor_state.rs` — exact-once paging across mid-row pauses,
  unknown/closed cursor conflicts, page-size and batch-cap errors,
  explicit truncation.
- `tests/http_api.rs` — real Axum router: concrete bodies/statuses,
  malformed-JSON envelope, cursor lifecycle over HTTP.
- `tests/trace_replay.rs` — run id, persisted intermediate state,
  categorized failure records, replay reproduction, arrow2 chunk shape.

## Checks not executed / limitations

These are explicit gaps, **not** claimed as passing:

- No performance benchmark run in CI; the selectivity comparison is an
  exact small-fixture counter assertion, not a wall-clock benchmark.
- No `cargo audit` / `cargo deny` / coverage-percentage gate is wired
  into `verify.sh` (the toolchains are not assumed installed). The test
  suite is the executed gate.
- Key type is limited to nullable signed 64-bit integers. Other ordered
  physical types are an extension point, not implemented.
- Exactly two predicates are supported by design; one-predicate or
  three-plus-predicate plans are rejected as `input/predicate_count`.
- The live-server HTTP smoke in `verify.sh` is skipped if `curl` is
  unavailable; HTTP behavior is otherwise covered in-process by
  `tests/http_api.rs`.
