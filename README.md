# IMAPlite — local fixture-backed constrained IMAP query service

A pure-backend **IMAP4rev1-subset** server whose mailbox content is entirely
**synthetic and local** (SQLite + generated/checked-in fixtures). It exists to
exercise and verify the hard parts of IMAP state rather than to manage real
mail:

- **sequence numbers shift as messages are deleted; UIDs are the stable
  identity**; a changed **UIDVALIDITY** invalidates every cached UID;
- command **tags are associated with their own responses**, literals are
  counted **by bytes**, and commands may be **pipelined/interleaved**;
- only **declared FETCH data items** are answered; unknown commands/items are
  rejected explicitly;
- concurrent observers of one mailbox observe a **single total order** of
  events.

There is **no general-purpose mailbox UI**. The surface is deliberately:
`CAPABILITY`, `NOOP`, `LOGIN`, `SELECT`/`EXAMINE`, `UNSELECT`, `LOGOUT`,
`FETCH`, `STORE`, `EXPUNGE`, and the `UID` variants (`UID FETCH`,
`UID STORE`, `UID EXPUNGE`). Everything else returns an explicit `BAD`.

---

## 1. Requirements & dependencies

- Go 1.22+ (standard library for networking and crypto).
- SQLite via the **pure-Go** driver `modernc.org/sqlite` — **no CGO**, no C
  toolchain. All dependencies are listed in `go.mod` / pinned in `go.sum`.
- Local-only. Plain TCP on loopback; no TLS, no real accounts, no external
  services. A separate loopback-only **control port** rotates UIDVALIDITY and
  reseeds fixtures for demos/tests.

Build with module cache / offline:

```bash
GOPROXY=off go build ./...     # deps are vendored via the module cache
# or normally:
go build ./...
```

## 2. Running the service

```bash
go run ./cmd/imaplite \
  -addr 127.0.0.1:1143 \
  -ctl-addr 127.0.0.1:1144 \
  -db /tmp/imaplite.db \
  -data ./data
```

Flags:

| flag         | default            | meaning                                    |
|--------------|--------------------|--------------------------------------------|
| `-addr`      | `127.0.0.1:1143`   | IMAP listen address                        |
| `-ctl-addr`  | `127.0.0.1:1144`   | loopback control address                   |
| `-db`        | temp file          | SQLite path                                |
| `-data`      | bundled `./data`   | fixture directory (`manifest.json`+`mail`) |
| `-max-literal` | `5242880` (5 MiB) | per-command literal byte budget           |

Synthetic accounts (from `data/manifest.json`):

| user     | password        | may select        |
|----------|-----------------|-------------------|
| `tester` | `Tester#2025!`  | `INBOX`, `ProjectX` |
| `watcher`| `Watcher#2025!` | `INBOX`           |
| `lit`    | `litpäss`       | `INBOX` (non-ASCII, used as a literal) |
| `admin`  | `Admin#2025!`   | any fixture mailbox |

Passwords are stored only as **PBKDF2-HMAC-SHA256** records (120k iterations,
per-user random salt) using the standard library; plaintext never enters
SQLite.

### Control port (line protocol, loopback only)

```
INFO <mailbox>      # counters: EXISTS UIDNEXT UIDVALIDITY
ROTATE <mailbox>   # bump UIDVALIDITY, clear messages (old UIDs go stale)
RESEED             # restore every fixture mailbox
QUIT
```

It refuses to bind to a non-loopback address.

## 3. Demo & tests

```bash
scripts/demo.sh       # builds, starts the server, runs all headline scenarios
scripts/run-tests.sh  # build + vet + go test -race -cover (unit + e2e)
```

Plain test invocation:

```bash
go test -race ./...                 # everything
go test ./internal/store/...        # one module
go test -v -run TestSequenceShiftButUIDStable ./test/e2e/
```

Tests **actually run**: unit tests per module plus a black-box suite in
`test/e2e` that connects over real TCP using an **independently written raw
IMAP codec** (it imports none of the server protocol packages), so expected
bytes are asserted against a separate implementation, not generated by the
code under test.

## 4. Error semantics (the four required failure families)

Every failure is a typed `imapwire.Error{Class, Code, Msg}` crossed from the
lower layers; the session maps it to an IMAP status without string matching.
Clients — and tests — can distinguish the families by **status + response
code**:

| Family (typed class)             | Typical cause                          | IMAP result                         |
|----------------------------------|----------------------------------------|-------------------------------------|
| **input error** `input-error`     | malformed set/syntax, bad args         | `BAD`                               |
| **unknown command/item**          | unimplemented verb or FETCH item       | `BAD`                               |
| **state conflict** `state-conflict` | command in wrong session state       | `BAD` (no code)                     |
| state conflict w/ declared code   | stale epoch / read-only / missing box  | `NO [UIDVALIDITY\|READ-ONLY\|NONEXISTENT]` |
| **auth failure** `auth-failure`   | bad credentials                        | `NO [AUTHENTICATIONFAILED]`         |
| **permission** `permission-denied`| account not allowed the mailbox        | `NO [NOPERM]` (checked before existence, so no oracle) |
| **resource exhaustion** `resource-exhausted` | literal/line/set over budget | `[TOOBIG]`, connection closed (stream cannot realign past an oversized literal) |
| **computation failure** `computation-failure` | malformed message / storage fault | `NO [PARSE]` / `NO [SERVERBUG]` |

Notes:
- `STARTTLS`/`AUTHENTICATE` → `BAD [UNSUPPORTED-STEPS]` (use `LOGIN`).
- After an **oversized literal** the connection is dropped with `BYE`: the
  declared payload bytes are still unread and the byte stream cannot be safely
  realigned. Semantic errors after a fully framed command keep the connection
  usable, and tests verify the next command still works.
- The per-connection structured log records the **run number** (command
  ordinal), entry state, key mailbox counters (`uidvalidity/uidnext/exists/
  first-unseen`), and the classified failure reason so a reported exchange can
  be replayed run by run.

## 5. Core state rules

- **Sequence number = ordinal among existing messages ordered by UID.** It is
  derived, never stored, so it shifts the instant a lower-UID message is
  expunged. `EXPUNGE` reports the *current* sequence number for each removal,
  renumbering after **each** deletion (RFC 9051): deleting original positions
  2 and 3 yields `* 2 EXPUNGE`, `* 2 EXPUNGE`.
- **UID is identity.** `UID FETCH <uid>` returns the same message content after
  its sequence number moved.
- **UIDVALIDITY is an epoch.** `ROTATE` bumps it and clears the mailbox; a
  still-selected session then answers every message-touching command with
  `NO [UIDVALIDITY]` and returns **no data** until it re-`SELECT`s the new
  epoch.
- **Literal length is byte count.** The binary fixture (UID 5) contains
  `NUL`, `0xFF`, embedded `CRLF`; `BODY[]` returns it byte-for-byte.
- **Total event order.** Mutations are serialized per mailbox
  (`broker.Mutate`) and fanned out through one goroutine; the acting
  connection renders its own events directly and is excluded from fan-out.
  Each FETCH record is assembled under a single write lock, so unsolicited
  events can never splice into the middle of a record. A slow observer whose
  queue fills is marked overflowed and disconnected rather than reordering
  everyone else's history.

## 6. Module boundaries (explicit data & error contracts)

```
cmd/imaplite/           runnable entrypoint + ctl adapter
internal/
  imapwire/   byte codec: Framer (atom/quoted/list/literal, "+ go ahead"),
              Conn (response framing), SeqSet, typed Error classes
  mimeparse/  constrained RFC 5322/MIME reader, BODY[] section extraction,
              ENVELOPE/BODYSTRUCTURE (returns ParseError → [PARSE])
  store/      SQLite persistence; derives sequence numbers; owns
              Expunge/ExpungeUID per-step renumbering, RotateUIDValidity
  broker/     per-mailbox serialized mutations + ordered fan-out
  auth/       PBKDF2-HMAC-SHA256 accounts, constant-time verify
  ctl/        loopback control line protocol
  fixture/    manifest + message loading + deterministic binary message
  server/     protocol state machine; routes commands, maps typed errors to
              IMAP status/codes, runs the observer pump
test/e2e/    independent raw-TCP black-box compatibility tests
data/        manifest.json and RFC 5322 fixture messages
scripts/     demo.sh, run-tests.sh
```

Data flows **up** as domain types/bytes and errors flow **up** as typed
classes; `server` is the only package that turns them into IMAP wire tokens.

## 7. Supported FETCH data items

`UID`, `FLAGS`, `INTERNALDATE`, `RFC822.SIZE`, `ENVELOPE`, `BODY`,
`BODYSTRUCTURE`, `RFC822` / `RFC822.HEADER` / `RFC822.TEXT`, and
`BODY[<section>]` / `BODY.PEEK[<section>]` including
`HEADER` / `TEXT` / `MIME` / `HEADER.FIELDS (…)` / `.NOT`, part paths
(`1`, `1.2`), and `<offset.count>` partials. Anything else is an explicit
`BAD`. `BODY[]` sections are returned as **raw wire bytes** with
content-transfer-encoding intact (per RFC 3501); non-existent parts omit the
item rather than failing the command.

## 8. Quick manual probe

```bash
go run ./cmd/imaplite -db /tmp/x.db &
{ printf 'L1 LOGIN tester Tester#2025!\r\n'; \
  printf 'S1 SELECT INBOX\r\n'; \
  printf 'F1 FETCH 1:5 (UID FLAGS RFC822.SIZE)\r\n'; \
  printf 'D1 STORE 2 +FLAGS (\\Deleted)\r\n'; \
  printf 'X1 EXPUNGE\r\n'; \
  printf 'L2 LOGOUT\r\n'; sleep 0.2; } | nc 127.0.0.1 1143
```

## 9. Security notes

- Loopback-only by default; credentials are synthetic fixtures.
- No hardcoded production secrets; PBKDF2 records only, constant-time compare,
  identical `ErrCredential` for unknown-user vs wrong-password (plus a dummy
  hash to flatten timing).
- Byte/line/literal/set resource budgets; parameterized SQL throughout.
- This is a local compatibility harness, **not** an internet-facing mail
  store; do not expose it beyond loopback.
