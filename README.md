# smtpsink — local-only SMTP drop service

A deliberately small SMTP service that speaks just enough of RFC 5321 to
**receive mail for local test mailboxes and persist it to SQLite**. It never
relays, never opens an outbound connection, and by configuration only binds to
loopback. It is intended for integration tests, offline development, and
teaching the SMTP transaction state machine — not for production mail.

## What is supported

| Command | Status | Notes |
|---|---|---|
| `EHLO` / `HELO` | ✅ | `EHLO` advertises `SIZE` and `8BITMIME`; a repeat greeting aborts the in-flight transaction per RFC 5321 |
| `MAIL FROM` | ✅ | angle-addr or bare addr, empty bounce path `<>`, `SIZE`/`BODY`/`SMTPUTF8` params tolerated |
| `RCPT TO` | ✅ | repeated recipients de-duplicated; only configured local domains are accepted |
| `DATA` | ✅ | RFC 5321 dot-transparency, end-of-data may straddle TCP segments |
| `RSET` | ✅ | clears the current transaction but keeps the greeting |
| `NOOP` / `QUIT` | ✅ | |
| `VRFY`, `STARTTLS`, `AUTH`, etc. | ❌ | answered `502 command not implemented locally` |

## Key guarantees (acceptance rules)

1. **Explicit command/transaction state.** `init → ready → mail → rcpt → data`.
   Out-of-sequence commands get `503`. DATA content is decoded in a dedicated
   state; the dot terminator split across packets is handled by the buffered
   reader.
2. **Partial recipient acceptance scopes delivery.** Each `RCPT` is accepted
   (`250`) or rejected individually (`550` not-local, `452` too many, `501`
   syntax). Exactly the set of accepted recipients gets a durable copy — a
   rejected/duplicated address never creates a row.
3. **No success before durability.** The final `250` is sent only **after** the
   SQLite transaction (message row + one copy row per recipient) commits with
   `synchronous=FULL`. On any storage error nothing is committed and the client
   receives `451` (temporary) or `452` (quota) — never a false `250`.
4. **Bounded resource use.** Per-command line length, per-DATA-line length
   (`1000` octets default), total message size (`SIZE` advertised and enforced),
   recipients per message, messages per connection, commands per connection,
   idle deadline, total session deadline, and a concurrent-connection gate.

### Failure → reply mapping

| Situation | Reply | Connection |
|---|---|---|
| Over-long command line (resyncable) | `500` | stays open |
| Over-long DATA line | `554` transaction failed | stays open, transaction reset |
| Unbounded line / framing lost | `421` | closed |
| Message exceeds size cap / declared `SIZE` | `552` | stays open |
| Sink temporary I/O error (incl. post-dot commit failure) | `451` | stays open, retry whole transaction |
| Storage quota exhausted | `452` | stays open |
| Peer disconnects before final dot | no reply (`<SILENT>`) | closed; nothing delivered |
| Idle / session deadline | `421` | closed |
| At connection capacity | `421` | closed |

Internal storage error text is **never** echoed to the peer; it is logged
locally with the session/message id and a failure category.

## Module layout (real modules, separated by concern)

```
cmd/smtpsink/            service entrypoint (flags, signals, wiring)
internal/config/         standalone JSON config + loopback-only validation
internal/wire/           byte codec: segmented line reader, length limits,
                         DATA dot-unstuffing, multiline reply writer
internal/protocol/       transport-agnostic SMTP state machine + path parsing,
                         recipient policy, failure taxonomy, log redaction
internal/storage/        SQLite Sink: one atomic transaction per message
internal/server/         loopback TCP host: deadlines, budgets, concurrency
configs/smtpsink.json    standalone configuration file
```

The protocol state machine has **no network imports**, so it is tested directly.
The compatibility tests speak real TCP using a small SMTP client written inside
the test files (not the code under test), and verify persisted rows through a
**separate, read-only `database/sql` connection** — reference answers are
hard-coded expectations, not generated by the implementation.

## Local quickstart

Requires Go 1.22+ (the SQLite driver may select a newer automatic toolchain;
the dependency is the pure-Go `modernc.org/sqlite`, so no C compiler is
needed at use time).

```bash
# dependencies are locked in go.sum
go build ./...

# run (loopback only), config defaults to configs/smtpsink.json
mkdir -p var
go run ./cmd/smtpsink --config configs/smtpsink.json
```

### Example session

```bash
$ swaks-less netcat session (or use scripts/example-session.sh)
$ exec 3<>/dev/tcp/127.0.0.1/2525
$ cat <&3 &    # 220 smtpsink.local SMTP sink ready
$ printf 'EHLO mylaptop\r\n' >&3
250-smtpsink.local greets mylaptop
250-SIZE 1048576
250 8BITMIME
$ printf 'MAIL FROM:<sender@localhost>\r\nRCPT TO:<bob@sink.local>\r\nDATA\r\n' >&3
250 sender OK
250 recipient OK
354 send message content, end with .
$ printf 'Subject: hello\r\n\r\nDot line: .starts-here\r\n.\r\n' >&3
250 message accepted as 9f3c…
$ printf 'QUIT\r\n' >&3
221 bye
```

A ready-to-run script that performs the above and then dumps the persisted row
with sqlite3 is provided:

```bash
./scripts/example-session.sh
```

### Inspecting stored mail

```bash
sqlite3 var/smtpsink.db \
  "SELECT id, sender, body_bytes FROM messages;"
sqlite3 var/smtpsink.db \
  "SELECT message_id, mailbox FROM recipient_copies ORDER BY mailbox;"
```

## Tests

```bash
# full suite with race detector and coverage
go test -race -cover ./...
```

Coverage per package is ≥ 80%. Independent tests assert concrete outcomes:

- **wire** — dot terminator split one byte per read; over-long line
  resynchronization then fatal unbounded overflow; dot-unstuffing table.
- **protocol** — command ordering, duplicate `RCPT` delivered once, mixed
  local/remote recipients scope the copy set, dot-prefixed body preserved
  byte-for-byte, `RSET` clears state, simulated sink failures (`451`/`452`),
  client abort during DATA delivers nothing, size/budget caps.
- **storage** — committed rows read via an independent DB connection; forced
  mid-transaction failure rolls back with no partial copy; quota rejection;
  durability across close/reopen; failure after Close.
- **server (real TCP)** — full EHLO→…→DATA transcript and reply codes, RSET
  over a socket, hard disconnect mid-DATA persists nothing, durability failure
  returns 451, over-long command then recovery, idle timeout 421, capacity 421.

## Diagnostics

Every log line carries a generated `session_id` (also the request correlation
id), remote address, and the current state (`state=rcpt|data|…`), plus a
`category` on failures (`timeout`, `line-too-long`, `fatal-overflow`,
`io-error`, `client-closed`). Accept/reject decisions say **why**
(`recipient rejected: not local`, `message rejected by declared SIZE`,
`delivery failed temporarily, no copy committed`).

Email addresses and EHLO identifiers are **redacted** in logs
(`alice@example.com` → `a***e@example.com`; message bodies are never logged).

## Key trade-offs / non-goals

- **Local-only by construction.** Config validation refuses any non-loopback
  bind host; there is no relay, MX lookup, or outbound socket at all.
- **No AUTH/STARTTLS** — traffic stays on `127.0.0.1`, so plaintext is
  acceptable for the stated local-testing purpose.
- Conservative mailbox syntax validation (not the full RFC 5321 address grammar;
  source routes / EAI are intentionally not supported).
- A single shared store connection serializes writes; adequate for a local test
  sink and keeps quota accounting race-free.
- Messages are stored as canonical CRLF bytes; no MIME parsing or de-fanging.
