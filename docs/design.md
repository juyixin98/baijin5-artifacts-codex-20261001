# 设计与边界语义

本文说明本地白名单 SOCKS5 CONNECT 代理的模块边界、关键机制的精确定义，以及
**哪些检查在当前环境无法执行**（单列，不写成“已通过”）。

## 1. 协议覆盖范围

实现 SOCKS5（RFC 1928）的一个受限子集：

- 支持：方法协商、用户名/密码认证（RFC 1929）、**CONNECT** 命令、地址类型
  IPv4(0x01)/域名(0x03)/IPv6(0x04)。
- 不支持并明确拒绝：BIND(0x02)、UDP ASSOCIATE(0x03)（回 REP=0x07
  command not supported）；GSSAPI(0x01) 等其它认证方法。
- 服务端**只提供一种**认证方法。配置 `auth.required=true` 时只提供 0x02，
  否则只提供 0x00。不提供“同时开放两种”，使协商结果无歧义、审计可归属到用户。

### 协商失败的明确终止

| 情形 | 线上字节 | 服务端后续动作 | 失败类别 |
|---|---|---|---|
| 客户端未提供可接受方法 | 发送 `05 FF` | 立即关闭，不读后续 | `no_acceptable_method` |
| VER ≠ 0x05（首字节即非 SOCKS5） | 不发送任何协议帧（该阶段无定义应答） | 立即关闭 | `protocol_version` |
| 认证子协商 VER ≠ 0x01、ULEN/PLEN=0 | 发送 `01 01` | 立即关闭 | `auth_subnegotiation` |
| 口令错误 | 发送 `01 01` | 立即关闭，不进入请求阶段 | `auth_denied` |
| 认证后端故障 | 发送 `01 01` | 立即关闭，日志级别 error | `auth_backend_error` |

“拒绝”与“后端错误”严格区分：`Authenticate` 返回 `(false,nil)` 是经过校验的
拒绝；返回 `(false,err)` 是基础设施故障，二者落库类别不同。

### 地址长度与形状校验

- IPv4 请求体固定 4 字节地址；IPv6 固定 16 字节；多一个或少一个字节都拒绝。
- 域名长度字段必须在 1..255，声明长度必须与实际一致（`ErrShortFrame` /
  `ErrExtraBytes` 分别归类）；标签语法在进入解析器之前校验。
- 读到的 `::ffff:1.2.3.4` 这类 v4-mapped IPv6 统一 `Unmap()`，按 IPv4 策略与
  ATYP=1 编码，避免同一地址两条策略路径。

## 2. 解析—策略—拨号一致性

域名请求的判定是**合取**：

1. 名字命中某条 `domain` 规则（精确名或“单标签通配” `*.suffix`），且端口命中；
2. 用配置的解析器解析名字；
3. 解析出的**每一个**地址都命中某条 `cidr` 规则（同一端口）。

三条中任意一条不满足即 `policy_denied` 或 `resolve_failed`。随后拨号阶段：

- 只对“上面已通过校验的地址”拨号，且拨号地址串是 **IP 字面量**，
  `net.Dialer` 绝不会再见到主机名，因此不存在“校验时的解析结果”和“连接时的
  解析结果”不一致的 DNS-rebinding 窗口。
- 多地址按解析器返回顺序去重后依次尝试；全部记录到 `attempts`（地址、
  outcome、错误串）。全部同类失败时返回该具体类别（如全 refused →
  `dial_refused`）；类别混合时返回 `dial_failed` 并保留逐次明细。
- 对 IP 字面量请求不做 DNS 解析，直接走 CIDR 判定。

### 通配规则的精确边界

`*.example.test`：匹配 `a.example.test`；**不**匹配 `example.test`（通配至少
需要一个非空标签）、**不**匹配 `a.b.example.test`（通配只跨一个标签）、
**不**匹配 `evilexample.test`（按标签边界比较，不做裸后缀匹配）。

## 3. 转发（relay）语义

两个方向各一个 goroutine，使用 32 KiB 缓冲，逐次 `Read`→完整 `Write`。

### 半关闭（half-close）

- 某方向 `Read` 返回 `io.EOF`：先保证本批次读到的字节已**全部写出**，再对
  该方向的对端写侧调用 `CloseWrite()`（TCP FIN）。**不**关闭整条连接，另一
  方向继续，直到它也结束或触发预算/错误。
- 只有读侧 EOF 触发半关闭；写侧错误、reset、超时按错误路径处理并拆除整条连接。
- 若对端不是 `*net.TCPConn`（测试替身可能不是），无法发 FIN，则仅结束该方向。

### 字节预算

- 每方向独立计数，初始为 0。**恰好转发到上限的那一批字节会被完整写出**，
  随后下一次读取前判定 `count >= limit` → 返回 `byte_budget_exceeded` 并拆除
  连接。因此“上限 N”表示“对端最多收到 N 字节”，边界可达、不越界。
- 预算在写出路径强制，即使对端用零散窗口接收（partial write）也逐段计数，
  统计值精确。

### 时间预算

- 协商阶段对**每次阻塞读**和**每帧写**分别设置 `handshake_timeout`，操作结束
  即清除。这样慢速/零窗口客户端的每次等待都有上界（防慢速攻击），而本地
  PBKDF2 口令推导、以及自带独立 context 超时的解析/拨号**不占用**协商预算
  （否则在 CPU 受限或 `-race` 插桩下，600k 轮哈希可能超过墙钟预算造成假超时）。
  客户端在任一读取点静默超过该超时 → `handshake_deadline`。
  协商读取次数固定（方法头/方法、认证 4 段、请求至多 2 段）且每帧长度有硬上界
  （请求 ≤262 字节），因此攻击者无法靠无限多的分段把协商无限拉长。
- 解析、每次拨号各自有独立超时 → `resolve_failed` / `dial_timeout`。
- relay 阶段在每次 Read/Write 前刷新空闲截止时间；任一方向静默超过
  `idle_timeout` → `idle_timeout` 并拆除整条连接。

### 连接预算

监听侧接受连接后先获取容量为 `max_concurrent_connections` 的信号量；已满则
**确定性地立即关闭**该连接并记录 `socks5_at_capacity`，不无限堆积已接受套接字。

## 4. 持久化与日志

- SQLite（WAL、单连接、busy_timeout）三张表：`rules`、`users`、`requests`。
- 口令只存 PBKDF2-HMAC-SHA256（600_000 轮、每用户 16 字节随机盐、32 字节
  派生键、迭代次数随用户存储）；校验使用恒定时间比较；未知用户也执行一次
  派生以减小用户枚举的时序差。
- 每个连接在协商开始时就插入一行，结束时更新；因此被中断/未完成的会话也
  留痕，不会“消失”。
- 结构化日志（默认 JSON Lines）每个事件带 `request_id` 关联，失败事件把
  `failure_category` 与 `failure_reason` 单列；`uncertainty` 单独承载无法由
  代理独立判定的结论。

## 5. 独立测试如何避免“自测自证”

- 测试客户端 `test/integration/rawclient.go` 按 RFC 手工拼/解字节，不 import
  任何代理侧编解码；另有第三方 `golang.org/x/net/proxy` 真实客户端兼容性用例。
- 期望值来自独立来源：回显服务器独立比对载荷；SQLite 用独立 SELECT 读回
  字节计数/类别/尝试；合成 resolver/dialer 由测试脚本给定，断言“被拒绝目标
  的拨号次数为 0”“解析调用次数为 0”“多地址尝试顺序”等**具体结果**。
- 覆盖场景：分段握手（每字节一写）、拒绝认证、`05 FF`、域名多地址回退、
  DNS-rebinding 否决、单向 EOF 后反方向仍完整、慢/静默上游空闲超时、字节
  预算精确截断、IPv4/IPv6、并发安全（`-race`）。
